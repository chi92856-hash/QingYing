# 清影 M-HUB 界面重制

## 资料分析
压缩包包含设计规格、交互逆向报告、提取令牌、功能事件、证据索引及一张首页截图。它描述的是硬件控制台，令牌存在局部覆盖和未确认默认值，不能作为完整官方规范。清影采用其黑灰中性表面、胶囊操作分组、24px 工作面板、16px 参数组及紧凑排版，不移植设备大图和硬件控制内容。

## 功能对应
| 现有能力 | 新版入口 |
|---|---|
| 批量链接、续传、剪贴板、静音、Cookie、Instagram 登录 | 链接下载 |
| 图片/视频框选、定位、撤销、清空、预览、修复保存 | 水印修复 |
| 关键词、话题、模式、排序、翻页、缩略图、选择下载 | 小红书采集 |
| 主页、目录、登录、照片/相册/视频/Reels、数量与暂停 | Facebook 主页 |
| 主页/评论图片、登录、预览、全选、选择下载 | X 图片采集 |
| 更新检查、打开目录 | 顶部操作区 |
| 原生完整功能与兼容入口 | 顶部“完整工具”；启动清影原版.cmd |

原 App 类的大部分方法直接保留已安装版本，仅更新既有的七个方法；新版界面通过桥接调用现有业务，不另写下载或修复算法。原版清影.exe 保留。新版为清影/清影-一体窗口.exe，依赖同目录 _internal，不能单独搬走。

## 启动修复
窗口程序启动时为缺失的 stdout/stderr 提供空输出，避免 CustomTkinter 字体提示造成 NoneType.write 异常。Windows 的本地界面通信改用随机名称、随机认证密钥的命名管道，避免 localhost 端口连接限制。网络平台登录仍使用原有独立浏览器与服务。

## 验证
通过 tools/check_bundle.py 对新版 EXE 的模块进行离线回归：配置原子保存、历史、RPC、Cookie、取消续传、采集、缩略图、X 媒体与侧栏。通过 tests/glass_bridge_checks.py 检查 X 表单、选择、操作路由和忙碌保护。JavaScript 语法检查通过。实际打开新版并查看链接下载、Facebook 及 X 页面；最终命名管道版在正常本机权限下启动成功。

未使用真实账号重新执行在线采集或下载，未执行更新下载安装。外部平台可用性仍取决于登录、网络与平台状态。

## 回退
运行“启动清影原版.cmd”。重制前 HTML/桥接源码和 EXE 备份在 backups 中。

## 顶栏调整
移除独立的系统标题栏，将窗口操作合并进应用顶栏。已实际验证最大化、还原、顶栏拖动与正常关闭。
